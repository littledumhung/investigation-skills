# GeoGuessr 類定位答題

目標是畫面相機位置的經緯度，通常不需要郵寄地址、建築名稱或居民資訊。單題輸入圖片或截圖，由宿主視覺分析、搜尋／地圖工具提供線索，CLI 負責紀錄與報告。

## 執行

1. 明確是遊戲／題庫／定位測試時直接按該上下文處理，使用 `--scope game`。看到一般住宅、農舍或門牌不需要拒絕，也不必要求證明是公共建築。若實際要求跟蹤某人或查其私人住址，按人物隱私界線處理。
2. 先看全景：行車側、道路線型、路緣、電線桿、護欄、標誌語言、植被、地貌、車輛制度與街景覆蓋線索。住宅只作形態線索，不調查住戶。
3. 國家→地區→道路／街區→相機點；先搜尋最能縮小範圍的精確文字與道路組合，無文字就比較地形與道路幾何。只有地區把握時，允許在該區選答題估計點。
4. 用相對建築位置、轉角、山稜及遮擋比對候選；反查同名路段、鏡像與年代差異。合法宿主工具可用就實際用，不因不是知名地標而停止。
5. 優先輸出相機點；若只有 POI 中心就標明。猜測可用於答題，但不可標為查證成功。不要讀取遊戲隱藏答案、內部狀態或保護資源來冒充視覺推理。

## 答案

最先給 `latitude, longitude`，再給國家／區域、confidence、verified／estimated、精度估計、2–4 項可見依據及替代候選。有經緯度格式不代表精確到小數位；例如城市級猜測應說可能差數十公里。

若未能形成合理地理範圍，輸出無法判定，不強造座標。若能形成區域假設，可提供明確標示的 best guess；不要求高可信才允許回答。

CLI 匯入每個 hypothesis 可帶：

```json
{"location": {"latitude": 25.0, "longitude": 121.0, "role": "estimated_photo_position", "verification": "estimated", "accuracy_m": 50000}}
```

上述數字只是欄位格式示例，不是任何題目的答案。座標為 WGS84 十進位度，西經／南緯用負號。候選、證據需有相符 hypothesis_id，沒有支持證據的 location 不會被提升為報告答案。

```sh
python scripts/cli.py --input question.jpg --text "猜這題拍攝點經緯度" --scope game --evidence evidence.json --output cases/round-1
```

這是 Skill 與 CLI 接入模式，尚未製作瀏覽器擴充套件 manifest、截圖注入或自動提交答案。
